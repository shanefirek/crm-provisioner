## P5 — Typed error hierarchy + retry-with-backoff on boundary errors

- **Deliverables:** `src/host/errors.ts` with `BoundaryError` (kinds: `transient` / `rate_limit` / `permanent`), `DataError`, `ConfigError`, `LogicError`. `retryBoundary<T>(fn, opts)` util with exponential-jittered backoff per the retry decision matrix (5 attempts transient/429, 3 timeout). Both adapters' HTTP wrappers classify and throw typed; `apply()` wraps calls in `retryBoundary`. `run_steps.error_code` becomes typed-class string ("BoundaryError:transient"); attempts count surfaces in result_json.
- **Gate:** memory-adapter unit step throws `BoundaryError{kind:"transient"}` → retried N times, recorded as `BoundaryError:transient` with `attempts: N`; `DataError` → not retried; SF_LIVE + ZOHO_LIVE regression green (no behavior change on happy path).
- **Defer:** P6 negative caching of permanent failures; P7 quality watchdog; circuit breakers (per principle's "when to defer" — wait until we've had an outage we needed one for); sub-classified error taxonomies beyond what's actually raised today (rule of three).

## P6 — Negative cache for permanent failures

- **Deliverables:** `permanent_failures` table keyed by `(connection_id, operation, target, payload_hash)` with `expires_at`. `plan()` checks the cache before emitting steps — non-expired hit → step diff = `blocked_by_prior_failure` with `notes` carrying original error + first_seen_at. `apply()` writes on permanent error class. `teardown_run` clears the row when its target is reversed. `force_retry_blocked:true` arg on `apply` bypasses (mirrors `confirm_destructive`).
- **Gate:** force a `DataError` step on memory adapter; second plan shows `blocked_by_prior_failure` with the original message in notes; `force_retry_blocked:true` bypasses; teardown of the failing target clears the cache (third plan shows `create` again); expired entries ignored.
- **Defer:** caching of transient retries (different lane); time-bucketed quotas (circuit breaker territory); per-error-code TTL renegotiation (use 30/90-day defaults); surfacing blocked-by-prior-failure in `inspect_instance` (plan only for now).

## P7 — Quality watchdog over the run

- **Deliverables:** `runs.aborted_by` + `watchdog_window_failures` columns. `apply()` per-step loop tracks trailing-window failure rate (default: window=10, threshold=0.5, min_steps=5); on trip throws `WatchdogError`, remaining steps recorded `skipped_by_watchdog`, run ends in `aborted` status with `aborted_by` set. Same shape for silent-success watchdog (10 consecutive noop/empty responses when create/update was expected).
- **Gate:** synthetic apply rigged to fail 6 of 10 steps trips watchdog after step 6; 4 of 10 does NOT trip (under threshold); silent-success scenario trips with `WatchdogError:silent_success_rate`; live smoke green (no regression on happy paths).
- **Defer:** configurable per-connection thresholds; resumability of aborted runs beyond teardown (operator decides whether to retry); time-window watchdogs; cross-run / cross-connection watchdogs (circuit breaker territory); streaming watchdog state mid-run.
